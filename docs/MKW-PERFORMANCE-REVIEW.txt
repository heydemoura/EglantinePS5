Direct mapped readback experiment (candidate 41)
Non-sparse allocations <=512 KiB, bounded 16 MiB live pool, persistent host
mapping and producer-range certificates. Only already-completed producers
qualify. GPU submission includes a HOST_READ visibility barrier; unfinished
or unknown writers fall back. Guest RAM is not imported. Asynchronous
snapshots retain staging. Mapping removes copies, not ordering requirements.

Follow-up: separate frontend and backend queue delay
Reanalyzed all five complete candidate-41 captures (75 frames, 17,238 reads)
without modifying the original evidence. Total queue delay partitions into
3,064.440 ms before frontend pop and 30.657 ms between pop and backend start.
Total read-call time across threads was 3,396.993 ms. The analyzer now exports
both partitions per read, per frame and per read type, and checks their sum
against the existing queue duration whenever all timestamps are present.
These are overlapping thread durations, not a frame-wall-time decomposition.

The main semaphore site (guest PC 0x856894d0 at observational guest address
0x2106235000) accounts for 74–85% of each window's call time; another PC at
the same address adds time in two windows. Most observations changed value.
The longest read took 40.186 ms, including 40.160 ms before pop, about 1.8 us
between pop and service, and 8.9 us in service. A clean cache at service does
not prove that these reads could safely bypass earlier commands.

An older candidate-38 Free Roam profile contains Vulkan command handoff,
macro processing and fence-drain waits ahead of reads. It is not synchronous
with candidate-41 events, so it does not attribute each long read to a specific
command. Next runtime evidence should correlate preceding-command execution
with each long read, including forced fence drains and command handoffs.
No frame-rate gain is claimed from this analyzer change. Read-only console
status was idle during this follow-up; no deployment or restart was performed.

could reuse consumers compiled with the original header while other objects

allocator and texture-cache object dependencies before packaging.

Follow-up candidate: bounded submitted command words
Profiles from the completed-semaphore trial identify DmaPusher::Step's safe
command reads as the dominant caller of diagnostic cache-flush timing. The new
opt-in experiment adapts Zortos submitted-word snapshots (cce6d44af2), including
GPU-written rejection and first-producer/continued-parameter ordering from
6612817cb4 and fae3bc64. It retains the current Zortos gitlink and other patches.

Each submission owns immutable words and checked entry offsets. A shared payload
lease caps one snapshot at 16 MiB and all live payloads/offsets at 64 MiB; at most
65,536 entries are captured. Overflow, exhausted budget or allocation failure
retain live reads. CommandList copies share one payload and one reservation.
At execution, synchronization precedes the GPU-written history check; GPU writes
remain disqualifying after their flush clears dirty state. Resumed entries,
continued parameters downloaded from the GPU, unknown mappings and dirty safe
reads also retain live reads. No guest RAM import or driver change is involved.

MKW_COMMAND_SNAPSHOT_MODE acknowledges same-process off/on controls. Bounded
selection counters show whether copied entries are actually executed. Complete

Submission-completion texture retirement (host verified; console pair queued)
The texture cache normally retains deleted images, image views and framebuffers
in eight-frame rings. Patch 0011 adds an opt-in alternative selected per boot by
EDEN_PS5_COMPLETION_RETIREMENT=1. Deletion records the Vulkan scheduler's current
submission tick, including commands still queued on its recording worker.
Only IsFree(tick), the completed GPU timeline, permits reclamation. The scheduler
advances the logical tick before queueing submission, so future recording does
not reuse an earlier submission's completion. No extra submit or wait is added.
Completed framebuffers, views and images are collected in that order before
pressure accounting and another eviction pass. Pending image-download ownership
and immediate-delete callers keep their existing behavior. Other backends and
the default path retain frame-based destruction.

observations, not a physical-pool total. It does not count all driver/CPU memory.
